# Harness Pocket → dsh-Go 能力对齐清单

> 基线：Harness Pocket 0.21.1（Android / Kotlin / Jetpack Compose）
> 对照：[ccch1mneyyy/dsh-Go](https://github.com/ccch1mneyyy/dsh-Go) 的公开 README 与目录
> 说明：dsh-Go 的 iOS 版仍在开发/真机测试，鸿蒙版也在推进中；它不是“已经完成三端”的成熟产品。本清单把它当作能力参照，不是要求逐项照搬。

## 0. 先定三个决策

在动手前先回答这三个问题，否则会做出两套半成品。

| 决策 | 选项 | 建议 |
|---|---|---|
| D1 产品定位 | A. 只做电脑 DSH 的轻量遥控器；B. 手机本身就是 DSH 主机 | 先选 A。B 是另一个产品，不是功能迭代 |
| D2 跨端路线 | A. 继续 Android 原生；B. Flutter 重写；C. Kotlin Multiplatform 共享核心 + 原生 UI；D. PWA 过渡 | 若 iOS/鸿蒙是硬需求，选 B 或 C；只求“先能用”，选 D |
| D3 是否做本机运行时 | 不做 / 做 PRoot Linux + Node + DSH | 默认不做；只有 D1 选 B 才启动 |

**结论：** 在没有确定 D1/D2 前，不要启动“手机本机运行 DSH”和“原生 iOS/鸿蒙”两条重工程线。

## 2. P0：必须做（先做这些）

### HP-01 流式事件通道（替代轮询）

**现状**
- `MainViewModel` 通过 `session/list` + `session/page` 轮询；消息落盘后才出现，没有逐字效果。
- 任务完成通知靠 4 秒轮询，最长 20 分钟。

**目标**
- 用 `/api/remote.mux` 的 `session/follow` 接收增量事件。
- 首次进入仍用 `session/page` 拉历史；后续走事件流。
- 断线自动重连、去重、从 `asOfSeq` 续传；失败时降级轮询。

**验收**
- 发送消息后 < 1 秒看到“生成中”状态。
- 工具调用、问答卡、审批、`turn/end` 都从同一事件流到达。
- 杀进程重开，能从服务端恢复，不重复消息。

**工作量**
- 5–8 人日（含协议兼容和回归）。

**风险**
- DSH 版本差异；必须保留轮询兜底。

### HP-02 远程推送与后台存活

**现状**
- `TaskMonitorService` 是 `dataSync` 前台服务，20 分钟上限；进程被杀就断。

**目标**
- 优先接 ntfy（自建、无 Google 依赖）；可选 FCM。
- 通知带 `sessionId`，点击直达会话。
- App 内提供“后台运行设置”引导（小米/华为/荣耀/OPPO/vivo）。

**验收**
- 锁屏、退到后台、进程被系统回收后，任务完成仍能收到通知。
- 通知权限关闭时有明确提示，不静默失败。

**工作量**
- ntfy 方案 3–5 人日；FCM 另加 2–3 人日。

### HP-03 令牌与传输安全

**现状**
- 令牌、Cookie 存在 `SharedPreferences` 明文；Manifest 开启 `usesCleartextTraffic`。

**目标**
- Android Keystore 加密保存 token/cookie；迁移旧数据。
- 默认只允许 HTTPS；HTTP 需用户显式确认“仅局域网/自担风险”。
- 可选证书固定（自建服务器场景）。

**验收**
- 备份/导出应用数据无法直接读出 token。
- 明文 HTTP 连接有二次确认和风险提示。

**工作量**
- 2–3 人日。

### HP-04 跨端决策落地

不要先写两套 UI。

- 选 **PWA**：1–2 周做核心聊天 MVP，3–4 周补图片/审批/问答；不是原生包。
- 选 **Flutter**：6–10 周重写核心；iOS 仍需 Mac/Xcode 签名，鸿蒙需 DevEco。
- 选 **KMP**：8–12 周；共享协议/数据层，iOS UI 仍要 SwiftUI。
- 选 **继续 Android**：明确告诉用户 iOS/鸿蒙暂不支持，不再承诺。

## 3. P1：高性价比远程体验

### HP-05 多主机管理

- 支持保存多个 `baseUrl + token + 别名`。
- 首页/设置可切换、测试连接、删除配置。
- 连接失败不覆盖当前可用配置。
- 验收：两台 DSH 实例来回切换，会话列表不串。
- 3–4 人日。

### HP-06 会话搜索与删除

- 服务端支持则走 RPC；不支持则在本地索引最近 N 条。
- 删除需二次确认；支持归档恢复。
- 验收：搜索标题/最近提问；删除后列表与网页端一致。
- 3–5 人日。

### HP-07 导出与分享（先本地）

- 单条回复生成 Markdown/图片分享卡。
- 整个会话导出 Markdown/JSON。
- 分享走系统 Share Sheet，不依赖服务端。
- 端到端加密链接/回放服务放 P2，不要一开始就做。
- 3–5 人日。

### HP-08 深色模式 / 平板 / 横屏

- Compose 主题拆成 light/dark；跟随系统。
- 宽度 ≥ 600dp 时抽屉常驻、内容居中；横屏输入框不遮挡。
- 验收：MuMu 平板/横屏截图回归；键盘弹出不遮输入。
- 5–8 人日。

### HP-09 国际化

- 抽取字符串到 `strings.xml`；先做中文 + 英文。
- 日期、Token、相对时间做 locale 格式化。
- 3–5 人日。

### HP-10 排队发送 / 插话

- 运行中可继续输入，进入队列；支持“立即发送”打断当前 turn。
- 依赖 DSH 的 steer/queue 能力；没有协议支持就只做本地队列，不假装已发送。
- 5–10 人日。

### HP-11 工程与发布

- CI：`assembleDebug` + 单元测试 + lint。
- `EventParser`/`HarnessApi` 的协议 fixture 测试（用真实事件脱敏样本）。
- 固定签名、版本号、SHA256、Release Notes 自动化。
- 2–3 人日。

## 4. P2：生态与差异化

### HP-12 插件 SDK / 原生工具卡

- 定义插件清单、工具卡 schema、表单/面板渲染协议。
- 先支持 3 种：确认类、表单类、结果面板类。
- 提供示例插件和开发文档。
- 这是 4–8 周级别的工程，不要在 P0/P1 前启动。

### HP-13 分享服务 / 对话回放

- 分享链接、端到端加密、浏览器回放页。
- 需要服务端、密钥管理、滥用防护、存储清理。
- 3–6 周（含服务端）。

### HP-14 SSH / DSRemote 接入

- 如果目标用户是“只有远程主机、没有公网 dsh web”的人群，再做。
- 需要单独的连接层和主机密钥管理。
- 2–4 周。

### HP-15 手机操控

- 无障碍读屏、点按、输入、三档确认、停止按钮。
- 高风险：隐私、误操作、应用商店合规。
- 与当前“AI 控制电脑”不是同一功能。
- 建议：**不做**，除非明确要转向“手机 agent”产品。

### HP-16 主题 / 图标 / 桌宠

- 低优先级；品牌素材有授权限制。
- 等核心稳定后再做。

## 5. P3：本机运行 DSH（只有 D1 选 B 才做）

这不是“对齐一个功能”，而是换产品形态：

- 内置 PRoot/Ubuntu、Node.js、DSH 运行时。
- 约 1 GB 安装体积；首次安装、升级、损坏修复。
- 后台保活、存储权限、CPU/内存占用、发热。
- 安全边界：本机执行工具、文件系统、网络。
- 参考 dsh-Go 的 runtime 目录，但不能直接复制品牌/素材；其主仓库 AGPL-3.0。

**工作量：** 4–8 周起步，且需要长期维护。若你的用户已经有电脑，优先做远程体验，不要做这条线。

## 6. 跨端路线对比

| 路线 | 周期 | iOS | 鸿蒙 | 代码复用 | 结论 |
|---|---|---|---|---|---|
| PWA | 2–4 周 | Safari 可用，非原生 | 浏览器可用 | 高 | 最快“能用”，不能上架 |
| Flutter 重写 | 6–10 周 | 需 Mac 签名 | 需 DevEco/插件 | 中高 | 最接近 dsh-Go 的路线 |
| KMP 共享核心 | 8–12 周 | SwiftUI 仍需写 | ArkTS 仍需写 | 中 | 适合长期双端 |
| 继续 Compose Android | 0 | ❌ | ❌ | 仅 Android | 只做单端 |

**建议：** 如果跨端是战略需求，先做 HP-01/02/03 把协议和连接层稳定，再选 Flutter 或 KMP；不要在现有 Compose 工程里直接“复制一份 iOS”。

## 7. 建议排期

### Sprint 0（1 周）
- 协议 fixture、单元测试、CI。
- token Keystore、HTTPS 默认策略。
- 明确 D1/D2，冻结跨端路线。

### Sprint 1–2（2 周）
- HP-01 流式。
- HP-02 ntfy 推送。
- HP-05 多主机。

### Sprint 3–4（2 周）
- HP-06 搜索/删除。
- HP-07 本地导出/分享。
- HP-08 深色/平板。
- HP-11 发布自动化。

### Sprint 5+
- HP-09 i18n、HP-10 排队。
- 根据 D2 启动 Flutter/KMP/PWA。
- 最后才评估 HP-12 插件、HP-13 分享服务、HP-14 SSH。

## 8. 不做什么（同样重要）

- 不要为了“像 dsh-Go”先做桌宠、主题、Live2D；这些不解决核心使用。
- 不要在远程版里塞手机操控；权限和合规成本极高。
- 不要在没有 Mac/Xcode 的情况下承诺“原生 iOS 包”。
- 不要在没有 DevEco/SDK 的情况下承诺“鸿蒙原生包”。
- 不要直接复制 dsh-Go 的 AGPL 代码到闭源分支；其品牌、Deepy、鲸娘素材也不在开源授权内。

## 9. 完成定义

每个条目完成时必须同时满足：

- 代码合并，`assembleDebug` 通过。
- 至少一个真实 DSH 会话回归（不是只有 mock）。
- 失败/断网/重连有明确 UI，不静默。
- README/更新日志/截图同步。
- 产物有版本号、SHA256、安装验证记录。

---

**一句话：** 你不需要把 dsh-Go 全抄一遍。优先补“流式、推送、多主机、搜索/分享、深色/平板、安全与 CI”，这些能把远程体验拉到同一水平；本机运行时、手机操控、插件生态和分享服务是另一个量级的投入，应该在产品定位明确后再做。
